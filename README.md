# 気分屋（kibunya）

自分の顔を覚えさせて、その日のコンディションを言い当てる **自分専用の小さな AI** を育てるアプリ。

毎日、顔を撮る → AI が見立てを出す → 自分で答え合わせをする。
その繰り返しで「顔のどこに自分のコンディションが出るか」を学習し、予測が当たるようになっていきます。
育つのは**予測精度**です。

```bash
pnpm install
pnpm dev      # http://localhost:5420
pnpm test     # Vitest
pnpm build
```

`pnpm install` の postinstall（`scripts/fetch-assets.mjs`）が、顔検出モデル（MediaPipe
FaceLandmarker）と wasm を `public/mediapipe/` に取得します。取得先は Google のモデル配布用
ストレージで、これは**開発者が手元でビルドを用意するための一度きりの通信**です。アプリ自体は
これらを同一オリジンの `/mediapipe/...` から読むだけで、ブラウザで動いている間は外部と一切
通信しません（詳しくは後述）。

`pnpm build` は `vite.config.js` で `build.target: 'esnext'` を指定しています。起動処理
（`src/app.js`）が最初の描画の前に IndexedDB からの読み込みをトップレベル `await` で待つため、
既定のビルドターゲットのままだとこの構文を変換できずビルドが壊れます。MediaPipe の
WASM/GPU 推論を使う時点でどのみち最新ブラウザ前提のアプリなので、`esnext` に上げています。

## 正直に書いておくこと

- 顔から気分や体調を読むことは、**科学的に確立していません**。
  このアプリがするのは、**あなた個人の中の相関を探すこと**だけです。
- 相関が見つからなければ「まだ顔から当てられません」と表示します。当たったふりはしません
  （`src/lib/model.js` の `usable` フラグ。的の R² が 0 以下＝「平均を答えるより悪い」なら、
  その的は予測もメーターも一切出しません）。
- **医療目的ではありません。** 診断でも助言でもありません。
- 顔写真も数値も、**この端末の外に出ません**。`src/` 以下のどこにも `fetch` や `XMLHttpRequest`、
  `WebSocket` の類は存在しません（下記「通信していないことの確認」を参照）。
  記録は IndexedDB に入ります。消すときは設定画面の「全部消す」から。

さらに、実装の過程で分かった 2 つの限界も正直に書いておきます。

### 表示される的中率は、わずかに甘めです

`src/lib/ridge.js` の `looPredictions` は「1 件抜いて学習し直したときの、その 1 件の予測」を
ハット行列で厳密に計算します（総当たりで学習し直した結果と一致することをテストで確認済み）。
ここまでは本当に「見たことのない日」に対する成績です。

ただし `src/lib/model.js` の `trainTarget` は、正則化の強さ λ を
`selectLambda(X, y)`（`src/lib/ridge.js`）で選んでいます。これは候補
`[0.1, 0.3, 1, 3, 10, 30, 100]` のそれぞれで LOO 誤差を計算し、いちばん小さいものを選ぶ処理です。
そして選んだあと、**同じ LOO の結果**（`loo = looPredictions(X, y, lambda)`）から的中率と R² を
そのまま報告しています。

つまり λ の選定が、採点に使うのと同じデータをすでに覗いています。これは
入れ子になった交差検証（λ の選定用と成績評価用で分離した検証）ではありません。
そのため画面に出る的中率・R² は、本当に未知の 1 日に対する成績よりも**わずかに楽観的**です。
水増しをしているわけではなく、λ を 1 つに固定して外側だけ LOO で測る場合と比べての話ですが、
数字を鵜呑みにしすぎないための注記として残します。

### 照明は「明るさ」しか打ち消せません

色にまつわる特徴量（肌の明るさ `skinTone`、目の下の暗さ `underEyeDark` など）は
`src/lib/features.js` の `extractFeatures` で、顔全体の平均輝度 `faceLum`
（`src/lib/faceColors.js` の `sampleFaceColors` が返す `faceMean` の輝度）で割って作っています。
これは部屋の照明が明るくなる／暗くなるという**一様な明るさの変化**は打ち消します
（「★色の不変性」テストで、r・g・b を同じ係数で掛けても値が変わらないことを確認済み）。

しかし、これで打ち消せるのは明るさだけです。照明の**色**（例: 白色灯から電球色に変わる）や
**向き**（例: 逆光・片側からの光）が変わると、顔の各部位が受け取る光の量や色みそのものが
場所ごとに違う比率で変わるため、全体の輝度で割るだけでは吸収しきれません。撮影は毎日
同じ場所・同じ明るさ（同じ光源）で行うことを強くおすすめします（セットアップ画面でもお願いしています）。

### グラフの「形」だけでは判断させません

「記録」画面の重ね折れ線グラフは、各系列をその系列自身の最小〜最大に引き伸ばして描きます。
そのため、本当は無関係な 2 本でも形が似て見えることがあります。だから形とは別に、生の値から
計算した本当の相関係数を必ず数字で併記します（`src/lib/chartData.js` の `describeCorrelation`。
例: 「相関 +0.42 — そこそこ一緒に動いています」）。こちらが本当の答えです。

## 仕組み

```
カメラ ─▶ FaceLandmarker ─▶ 顔座標系に正規化 ─▶ 特徴量15本 ─▶ Zスコア(自分基準・プール更新)
                              ▲                                    │
                        品質ゲート                                  ▼
              （向き/傾き/大きさ/明るさ/ブレ）           リッジ回帰 ─▶ 予測＋自信度
                                              （毎回LOOでλ選定＋的中率を再計算）
```

### 1. 顔座標系（`src/lib/faceFrame.js`）

**顔の見た目は、体調よりも「撮り方」で変わります。** 距離・角度・照明が毎日違えば、
測っているのは体調ではなくカメラです。そこで、顔そのものを基準にした座標系に移します。

- 原点 = 両目の内眼角の中点
- 単位 = 内眼角間距離を 1.0
- 回転 = 目線が水平になるよう補正

これで撮影距離と傾きの差が消えます。「回転・拡大・平行移動しても特徴量が変わらない」ことは
テストで保証しています。

消せない差（顔の向き・明るさ・ブレ）は**撮影品質ゲート**（`src/lib/quality.js`）で弾き、
全項目が緑のときだけシャッターを切ります。「顔の向き」は、MediaPipe が返す 4x4 変換行列の
前方向ベクトルの z 成分だけから 1 つの角度に落とした「正面からのズレ」で判定します
（`src/lib/faceFrame.js` の `offAxisDeg`）。Euler 角の yaw・pitch に分解しないので、
分解の規約（どの軸から先に回すか）に依存せず、左右に傾いても上下に傾いても公平に弾けます。
首の傾き（ロール）だけは別枠で、顔座標系を作るときの回転量 `rollDeg` をそのまま使います。

### 2. 判断はすべて「自分のベースラインからのズレ」

初回に平常時の顔を 5 枚撮って、各特徴量の平均と SD を作ります（`src/lib/baseline.js` の
`buildBaseline`）。ただし、この 5 枚は**同じ一回の撮影**なので、その SD は日ごとの変動ではなく
その場のわずかなブレしか表していません。それで割ると、平均が 0 付近の差分系の特徴量
（目の開きの左右差・口角の上がり・目の下の青みなど）は毎日クランプ（±6 SD）に張り付いて、
情報が消えてしまいます。

そこで、記録が増えるたびに、セットアップの 5 枚と**これまでの記録すべての生の特徴量**を
混ぜて平均と SD を取り直します（`pooledBaseline`）。記録が増えるほど基準が実態に近づきます。
毎日の Z スコアはこのプールされた基準からのズレとして計算されます。他人と比べることは
一切しません。

### 3. リッジ回帰と、嘘をつかない的中率（`src/lib/ridge.js` / `src/lib/model.js`）

切片を罰則から外した拡張設計行列で `w = (XᵀX + λP)⁻¹Xᵀy` を解きます。
λ は Leave-One-Out 誤差が最小になるものを候補から選びます。

LOO はハット行列の対角を使って `e_i /(1 − h_ii)` で一撃で出します。これは近似ではなく、
**1 件抜いて学習し直した結果と厳密に一致します**（総当たりとの一致をテストで確認しています）。
だから「育ち」画面に出る的中率は、学習データに対する成績ではなく、見たことのない日に対する
成績です（ただし λ の選定自体もこの LOO を覗いているため、わずかに楽観的です。詳しくは
上の「表示される的中率は、わずかに甘めです」を参照）。

R² が 0 以下（＝平均を答えるより悪い）の的については、予測を出しません。

## 通信していないことの確認

`src/` 以下を対象に、`fetch` / `XMLHttpRequest` / `WebSocket` / `sendBeacon` /
`navigator.sendBeacon` / `http://` `https://` の URL 文字列を検索すると、1 件もヒットしません。
アプリの実行コード（ブラウザで動く部分）には、外部と通信する経路がそもそも存在しません。

顔検出モデル（`/mediapipe/face_landmarker.task`）と wasm（`/mediapipe/wasm/...`）は、
ビルド前に `scripts/fetch-assets.mjs`（`pnpm install` の postinstall、Node.js 側のスクリプトで
`src/` の外）が一度だけ取得して `public/` に置いたものです。ブラウザで動く `src/face/detector.js`
はこれを `FilesetResolver.forVisionTasks('/mediapipe/wasm')` /
`modelAssetPath: '/mediapipe/face_landmarker.task'` として**同一オリジン**から読むだけで、
実行時に外部ホストへ出ることはありません。

## テスト

`src/lib` の純粋関数と、それらをつなぐ `src/pipeline.js` をテストしています
（カメラと DOM はテストしません）。現在 19 ファイル・426 個のテストがすべて通ります。

```bash
pnpm test
```

対象は、幾何の不変性（`faceFrame` / `features`）、色の不変性、撮影品質ゲート
（`quality`）、ベースラインの Z 化（`baseline`）、リッジ回帰と LOO の厳密一致・重み回収
（`ridge`）、学習と usable 判定（`model`）、しゃべり方（`persona`）、グラフ用の正規化と
相関計算（`chartData`）、似ている日の検索（`neighbors`）、タグ（`tags`）、サムネイルの
リサイズ計算（`thumbnail`）、書き出し/読み込みデータの検証（`dump`）、見立てと答え合わせの
当たり判定（`verdict`）、カメラ無しで検証するための合成データ生成（`synthetic`）まで、
このアプリの判断ロジックのほぼ全体をカバーしています。

カメラの無い環境では、`window.__app` から注入して確認できます（`src/app.js`）。

```js
window.__app.feedLandmarks(landmarks, { matrix, image, width, height }) // 撮影1回分を解析
window.__app.zOfLast()          // 直近の解析結果を現在の基準でZ化して返す
window.__app.getState()         // 内部 state をそのまま返す
await window.__app.setBaselineFrom(featureList) // features の配列からベースラインを作って保存
await window.__app.reload()     // DB から読み直して再描画
await window.__app.reset()      // 全データを消してセットアップからやり直す
await window.__app.seedDays(40) // 相関のある合成データを40日分投入（体調・眠さは学習できる想定、気分はできない想定）
```
