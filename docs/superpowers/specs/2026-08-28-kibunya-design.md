# 気分屋（kibunya）— 設計仕様

作成日: 2026-08-28

## 1. これは何か

自分の顔を覚えさせて、その日のコンディション（体調・気分・眠さ）を言い当てる
**自分専用の小さなAI**を育てるブラウザアプリ。

毎日、顔を撮る → AIが見立てを出す → 自分で答え合わせをする。
この繰り返しで「顔のどこに自分のコンディションが出るか」をAIが学習し、
予測が当たるようになっていく。育つのは**予測精度**であって、キャラクターではない。

すべて端末内で完結する。サーバーに顔も数値も送らない。

## 2. 前提と限界（アプリ内とREADMEに明記する）

- 顔から気分・体調を読むことは科学的に確立していない。
  このアプリがやるのは **利用者個人の中の相関を探すこと** だけ。
- 相関が見つからなければ「当てられません」と表示する。当たったふりはさせない。
- 医療目的ではない。診断でも助言でもない。
- **顔の見た目は体調よりも「撮り方」で変わる。** 距離・角度・照明が毎日違えば、
  測っているのは体調ではなくカメラである。したがって「顔そのものを基準にした
  正規化」と「撮影品質ゲート」が本アプリの中核であり、省略できない。

## 3. スコープ

### 作るもの
- 初回セットアップ（ベースライン取得）
- 「今日」画面: 撮影 → 予測 → 答え合わせ
- 「育ち」画面: 的中率・学習された重み・学習曲線
- 「記録」画面: 一覧・推移グラフ・似ている日・タグ分析・サムネイル振り返り
- 「設定」画面: ベースライン再取得・エクスポート/インポート・全消去

### 作らないもの（YAGNI）
- アカウント、同期、共有、SNS 連携
- ニューラルネットワーク（この規模のデータでは線形に負ける）
- 複数人のプロファイル
- 通知・リマインダー（フェーズ外。必要になったら足す）

## 4. 技術スタック

- Vite + 素の JavaScript（ビルドツール以外のフレームワークなし）
- Vitest（`src/lib` の純粋関数）
- `@mediapipe/tasks-vision` の FaceLandmarker（478 landmarks + facialTransformationMatrix）
  blendshapes は使わない。特徴量はすべて幾何と色から自分で作る
- IndexedDB（記録・ベースライン・サムネイル・設定）
- 開発ポート **5410**

既存の同系プロジェクト（掌鑑・呼吸法トレーナー・ユビサキ魔法）と同じ流儀に揃える。

## 5. アーキテクチャ

```
カメラ ─▶ FaceLandmarker ─▶ 顔座標系に正規化 ─▶ 特徴量15本 ─▶ Zスコア(自分基準)
                              ▲                                    │
                        品質ゲート                                  ▼
                  （向き/大きさ/明るさ/ブレ）        リッジ回帰 ─▶ 予測＋自信度
                                              （毎回LOO交差検証で的中率を再計算）
```

## 6. 中核 ① 顔座標系（`lib/faceFrame.js`）

写真は撮るたびに距離も角度も変わる。画素座標のままでは「目が小さい」が
撮り方で変わってしまう。そこで **顔そのものを基準にした座標系** に移す。

- 原点 = 両目の中点
- スケール = 両目の内眼角間距離を 1.0 とする
- 回転 = 左右の目を結ぶ線が水平になるよう補正（roll 除去）
- 顔の向きは `facialTransformationMatrix` の前方向ベクトルから「正面からのズレ角」1 本で扱う
  （Euler 角の分解規約に依存しないため。yaw と pitch をまとめて 1 つの数字にする）

**不変性の要件**: 同じ顔を回転・拡大・平行移動した landmarks から、
同一の特徴量が出ること（許容誤差 1e-6）。これはテストで保証する。

## 7. 中核 ② 撮影品質ゲート（`lib/quality.js`）

正規化しても消せない差（顔の向き・照明）は、撮らせない方向で対処する。

| 項目 | 条件 | 理由 |
|---|---|---|
| 正面からのズレ | ≤ 10° | 横や上下を向くと片側の特徴量が潰れ、顔幅も変わる |
| roll | \|roll\| ≤ 10° | 正規化で消せるが大きいと精度が落ちる |
| 顔の大きさ | 内眼角距離が画面幅の 8〜20% | 小さすぎると分解能不足 |
| 明るさ | 顔領域の平均輝度 60〜200 / 255 | 白飛び・黒潰れを弾く |
| ブレ | フレーム間の landmark 平均移動量 ≤ 0.006（正規化画像座標） | 動いている最中を撮らない |

全項目が緑になったら 3 秒カウントダウンして自動シャッター。
初回セットアップも毎日の撮影も **まったく同じゲートと同じ手順** を通す。

## 8. 特徴量 15 本（`lib/features.js`）

すべて顔座標系の値、または顔全体の平均輝度で割った相対値。
そのうえで `baseline.js` により **自分のベースラインからの Z スコア** に変換して使う。

| # | 名前 | 中身 |
|---|---|---|
| 1 | `eyeOpenL` | 左目の縦横比（EAR） |
| 2 | `eyeOpenR` | 右目の縦横比 |
| 3 | `eyeOpenAsym` | 左右の目の開きの差 |
| 4 | `lidHeavy` | 上まぶた縁 〜 眉 の距離 |
| 5 | `underEyeDark` | 目の下領域の輝度 − 頬の輝度（顔平均輝度で正規化） |
| 6 | `underEyeBlue` | 目の下の 青み/赤み 比 |
| 7 | `faceWidthLower` | 下顔幅 / 内眼角距離（むくみ） |
| 8 | `cheekFullness` | 頬の輪郭の膨らみ |
| 9 | `jawSharp` | 顎ラインの角度 |
| 10 | `mouthCornerLift` | 口角の高さ − 口中央の高さ |
| 11 | `browHeight` | 眉の高さ |
| 12 | `browFurrow` | 眉間の狭さ |
| 13 | `asymmetry` | 顔の左右対称性スコア |
| 14 | `skinTone` | 頬の明度（顔平均輝度で正規化） |
| 15 | `skinRed` | 頬の赤み（R/(R+G+B)） |

色を使う 5・6・14・15 は照明の影響を受けやすい。顔全体の平均輝度で割った
相対値にして吸収するが、それでも残る差は限界として認め、README に書く。

## 9. 中核 ③ 学習（`lib/ridge.js` / `lib/model.js`）

### モデル

- 入力 X: n 日 × 15 特徴量の Z スコア行列
- 出力 y: 体調 / 気分 / 眠さ（各 1〜5）。3 本を独立にフィットする
- リッジ回帰の閉形式: `w = (XᵀX + λI)⁻¹ Xᵀy`（切片は中心化で処理）
- λ は候補グリッド `[0.1, 0.3, 1, 3, 10, 30, 100]` から **LOO 誤差が最小** のものを選ぶ

### 閉形式 LOO

ハット行列 `H = X(XᵀX + λI)⁻¹Xᵀ` を使い、LOO 残差は `e_i / (1 − h_ii)`。
n 回フィットし直す必要がないので、毎回リアルタイムに真の汎化性能が出せる。
**総当たり LOO と一致すること** をテストで保証する。

### 表示する指標

- **的中率**（主指標）: LOO 予測が実測の ±1 段階以内に入った割合。直感的
- **R²**（補助）: LOO 予測の決定係数。負なら「平均を答えるより悪い」＝学習できていない
- 3 ターゲットそれぞれ独立に出す。「体調は当てられるが気分は当てられない」を許す

### 予測しない条件

- 記録が 5 件未満 → 予測せず「まだあなたのことがわからない」
- LOO の R² が 0 未満 → 「まだ当てられません」と表示し、数値だけ見せる

### 自信度

`データ数` と `LOO R²` と `今日のZスコアがベースライン分布のどれだけ内側か` の 3 つから
0〜1 を出す。自信が低い日は気分屋らしく曖昧な言い方になる（`persona.js`）。

### 学習された重み＝AIが自分について学んだこと

Z スコアで学習しているので重みはそのまま比較可能。絶対値の大きい順に日本語化し、
「あなたの"体調"は 目の開き・頬のむくみ・口角 に出ます」と提示する。

## 10. 似ている日（`lib/neighbors.js`）

今日の Z スコアベクトルと過去の各日のユークリッド距離を取り、近い順に 3 日を返す。
根拠表示に使う（「この顔、3/12 とそっくり。あの日は"寝不足"だった」）。
予測そのものには使わない（予測はリッジ回帰が担当）。

## 11. データモデル（IndexedDB）

```
baseline  : { id: 'current', createdAt, mean: {featureName: number},
              sd: {featureName: number}, sampleCount }
entries   : { date: 'YYYY-MM-DD', capturedAt, features: {name: raw},
              z: {name: number}, quality: {...}, labels: {...}, prediction: {...} }
thumbs    : { date: 'YYYY-MM-DD', blob }   // 小さい JPEG（長辺 240px, quality 0.7）
settings  : { id: 'app', keepThumbnails: true, ... }
```

- 1 日 1 件。撮り直した場合は同じ日付を上書きする
- サムネイルは既定で保存する（記録画面で顔の変化を見返せる）
- **顔画像そのものは端末内にしか存在しない**。全消去ボタンは設定画面の最上部に置く

### ラベル（`lib/labels.js`）

- スライダー 3 本: `condition`（体調）/ `mood`（気分）/ `sleepiness`（眠さ）各 1〜5
- タグ（複数選択、自由追加可）: 寝不足・むくみ・頭痛・忙しい・飲んだ翌日・風邪気味・
  運動した・よく寝た・生理・ストレス
- タグは予測の入力には使わない。**分析用**（タグあり日 vs なし日の特徴量差）

## 12. 画面

### 初回セットアップ
カメラ許可 → ガイド枠 → 品質ゲート → 自動シャッター × 5 枚
→ ベースライン（各特徴量の平均・SD）を作成 → 「これがあなたのふつうの顔です」

### 今日
1. 撮る（セットアップと同じゲート・同じ手順）
2. AI の見立て: 体調 / 気分 / 眠さ の 3 メーター＋気分屋のひとこと＋自信度
3. 答え合わせ: スライダー 3 本＋タグ
4. 送信後「当たってた / 外してた」を表示し、その場で再学習

### 育ち
的中率メーター（3 ターゲット × LOO）、データ数、AI が学んだこと（重み上位の日本語化）、
学習曲線（データが増えるにつれ的中率がどう動いたか）。

### 記録
カレンダー一覧、特徴量の推移 vs 自己申告の推移の重ねグラフ、似ている日 TOP3、
タグ別平均、サムネイルの振り返り。

### 設定
**全データ消去**（最上部）、ベースライン再取得、サムネイル保存の ON/OFF、
JSON エクスポート / インポート。

## 13. テスト戦略

`src/lib` の純粋関数を Vitest で。UI とカメラはテストしない。

| テスト | 何を保証するか |
|---|---|
| 不変性テスト（最重要） | landmarks を回転・拡大・平行移動しても特徴量が同一 |
| 重み回収テスト | 既知の重みで作った合成データからリッジが重みを取り戻せる |
| LOO 一致テスト | 閉形式 LOO が総当たり LOO と一致（誤差 1e-9） |
| λ 選択 | ノイズが多いデータでは大きい λ が選ばれる |
| 予測しない条件 | n<5 と R²<0 で正しく「わからない」を返す |
| 品質ゲート | 各閾値の境界で正しく通す/弾く |
| ベースライン | 平均・SD・Zスコアの計算、sd=0 のゼロ除算回避 |
| persona | 同じ入力なら同じ出力（決定的） |

### ヘッドレス検証（`window.__app`）

- `window.__app.feedLandmarks(landmarks, colorSamples)` — カメラなしで撮影1回分を流す
- `window.__app.seedDays(n)` — 合成データを n 日分入れて「育ち」「記録」画面を確認
- `window.__app.reset()` — 全消去

ヘッドレスブラウザでは `getUserMedia` が使えないため、この注入口が唯一の検証手段になる。

## 14. 実装フェーズ

1. **顔を覚える** — カメラ、FaceLandmarker、品質ゲート、顔座標系、特徴量、ベースライン
2. **記録する** — 今日画面、答え合わせ、IndexedDB 保存、サムネイル
3. **育てる** — リッジ回帰、LOO、予測、自信度、persona、育ち画面
4. **振り返る** — 記録画面（推移グラフ・似ている日・タグ分析・サムネイル）＋設定画面

各フェーズは独立して動く状態で終える。フェーズ 1 が終われば「自分の顔の特徴量が見える」、
フェーズ 2 で「記録がたまる」、フェーズ 3 で「予測が出て育つ」、フェーズ 4 で「振り返れる」。
